# Roster design

- Start with the conductor and the fewest durable specialists that reduce
  the owner's coordination burden. Add or split a role only when recurring work
  needs distinct context, an independent check, or a separate cadence; merge
  or retire overlaps.
- Name roles for stable domains or outcomes, never a temporary phase such as
  “Design”; names bias behavior and must match the end-to-end responsibility.
- Horizontal roles are limited to independent verification and centralized
  coordination/release. Product, UX, planning, and implementation stay with
  the vertical domain owner.
- Every active roster entry has exactly one attached `RESPONSIBILITY.md`; a
  second role file is folded and retired. Live status stays in the thread's
  actor-bound structured plan, not the bootloader.
