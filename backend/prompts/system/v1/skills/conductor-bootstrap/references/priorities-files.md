# Priorities files

Use this when you write, review or suggest a change to a priorities file: at setup, when an agent is created, and in the weekly instruction review.

## Two levels

- **The project's file:** `context/PRIORITIES.md`. What the whole team puts first.
- **Each agent's file:** `PRIORITIES.md` in that agent's own `context/` folder (`.threads/<agent id>/context/`). Its Now is the problems that agent is there to solve, in order. A project line the agent serves may be one of them.
- An agent in a project loads both on every turn, so keep each to a few short lines. An agent outside any project has only its own file. A priority the person states for themselves outside a project goes in the file of the agent whose work it is, as a line serving that agent's aim.

## What a file holds

- **Use line:** the file opens with this line, in italics, and keeps it: `*Use: when two pieces of work compete, the one higher under Now goes first. The person owns this file; agents suggest changes and never edit it.*` Put the person's name in place of "the person" only if they gave it.
- **Now:** only the problems the person said come first, in their order. A line names a problem or what the person wants, never a task: tasks stay in plans. A date they give goes under Dates, not Now.
- **Always:** only kinds of work the person said this agent may start without asking, where that differs from the project's file.
- **Dates:** only dates the person set.
- **Waits** and **Goes first, whatever is above** (the project's file only): what does not start yet, and what jumps the order (something that stops a person or an agent working today).
- **Never in a file:** goals, budgets, single incidents, or rules for one kind of work. Goals are long-term and live with the project's or the agent's own description of its work; a priorities file says only what comes first now. A rule for one kind of work goes in that work's workflow or skill.

## How to fill one

- Every line traces to the person's words or a decision they made, or reads `Not set yet`. Never fill a gap with what seems likely.
- Use the person's own words, not reworded: a rewording can add something they never said. Keep the words that say what is wrong or what they want; a topic alone is not a problem. No platform terms or jargon.
- For each new agent, whoever creates it (the project's conductor, or CORSIA for an agent outside any project) asks the person what that agent should solve first. Its Now holds what they name, in their order, or reads `Not set yet` if they name nothing.
- Each Now line serves a goal of the project or of the agent; for an agent outside any project, its aim is what the person named for it, and CORSIA's is what the person said they are working toward. When a line serves none, ask the person about it; never write it in silently.
- The person approves each file. A file they have not approved does not count.

## What it starts

An agent moves a task out of Later only when the task fits a line the person approved, and it names that line when it does. Until the person approves an agent's own file, only the project's file counts; an agent outside any project has none until then. Nothing else leaves Later. An agent with no approved line it can work on, Now or Always, in either file, stays asleep: it starts nothing on its own.

## Who changes it

- The person owns every priorities file. Agents, the lead agent included, only suggest changes and never edit one directly.
- Changes are rare. When a Now line's problem is solved, the agent that solved it suggests removing the line. The weekly instruction review also looks for stale lines and suggests removing them.
