# Offering a local model

Use this for first-run task 2 when no local model is connected (install skips it when a subscription works), and any time later the person asks for one.

1. Read `corsia_api` `GET /api/providers/local/setup`. If `state` is `starting` or `downloading`, setup is already under way (the setup screens start one): make no offer; follow **Setup already running** below. Otherwise re-check with `model_sources` `recheck: true`: if a local model is connected, make no offer. If the state is `ready` but none is connected, say setup ended without a model and offer a retry (step 3). If it is `setup_failed`, `start_failed` or `failed`, report it as below before offering a retry. Read `local_model`. If its `state` is `low_memory`, setup has no model for this computer: say nothing and move on. If it is `picked`, its `model` names the model (`name`) and its size (`download_size_gb`); when its `message` is not null, the model is CORSIA's starter model, not oMLX's pick, so pass the `message` on instead of saying oMLX picked it. If it is `not_checked`, `checking` or `failed`, the model is unknown until setup asks: make the offer without a name or size. oMLX picks the model for this computer (CORSIA's starter model when oMLX has none), never you; never name another.
2. Ask once, in chat, then end your turn and wait:

> A model that runs on this computer is for work you'd rather keep local and for background jobs. I'd set up [name] ([download_size_gb] GB). It downloads in the background, and the app shows progress. It uses memory while it's loaded. Installing it doesn't move any work by itself; afterwards I can point particular agents or jobs at it if you want. Set it up?

With no model picked, say `the model that suits this computer best` in place of `[name] ([download_size_gb] GB)`.

3. Yes: `POST /api/providers/local/setup` with body `{}`; setup installs the model it picked. The disk needs room for the rest of the download plus 10%. Report progress truthfully from `GET /api/providers/local/setup` (`state`, `percent`, `stalled`); never promise a speed. A `409` with `detail.code` `consent_required` means an unregistered copy of oMLX is running on this computer: ask `Another copy of oMLX is already running on this computer. Stopping it ends it now, so anything using it stops too (if it starts at login, it comes back at your next login). Keeping it runs two copies, which uses more memory. Stop it or keep both?` then resend the same request with `"other_omlx": "stop"` or `"keep"`. A `409` `foreign_omlx_changed` means the running copies changed since you asked, or stopping them failed: ask again, then resend; on a second one, offer to keep both instead. If it is still `downloading`, follow **Setup already running**; do not start it again.
4. No: move on. Don't re-offer unless they ask.

## Setup already running

It runs on its own and never holds up a setup task. For `starting`, post `Your local model is starting in the background. Your agents can use it once it's ready.` For `downloading`, post `Your local model is downloading in the background: [percent]%. Your agents can use it once it's done.` Omit the percent when it is null; if `stalled` is true, say the download is paused and continues when the connection returns. Then carry on with the rest of task 2. The setup screens' download sends a wake (`onboarding.local_download`) when it ends: never read it again unless the person asks, and post that news as `first-run-app.md` does. A download you started in step 3, or one found on the script path (`first-run.md`; the installer's sends no wake), you follow yourself: read the route again at the end of each later setup task and whenever the person asks, and say nothing while it still runs unless asked. The first time it reads `ready`, re-check `model_sources` and, if connected, post `Your local model finished setting up. Your agents can use it now.` For `stopped`, say setup is stopped; never claim it completed or failed. For `setup_failed`, `start_failed` or `failed`, say once what failed: setup, starting the downloaded model, or the download respectively. Pass on its `fix` in plain words, plus `ref` when present, but offer the retry yourself instead of its Settings pointer: on yes, resend the step 3 POST. For `cause: memory` offer no retry. If it is still `downloading` at the wrap-up, add the clause `The local model is still downloading; the app shows its progress.`
