# Offering a local model

Use this for first-run task 2 when no local model is connected (install skips it when a subscription works), and any time later the person asks for one.

1. Read `corsia_api` `GET /api/providers/local/setup`. If `state` is `starting` or `downloading`, setup is already under way (the setup screens start one): make no offer; follow **Setup already running** below. Otherwise re-check with `model_sources` `recheck: true`: if a local model is connected, make no offer. Existing registered local servers and their models stay in use unchanged. If the setup state is `setup_failed`, `start_failed` or `failed`, report it as below before offering a retry. Read `local_model`. If its `state` is `low_memory`, setup has no model for this computer: say nothing and move on. If it is `picked`, its `model` names the model (`name`) and its size (`download_size_gb`); when its `message` is not null, the model is CORSIA's starter model, not oMLX's pick, so pass the `message` on instead of saying oMLX picked it. If it is `not_checked`, `checking` or `failed`, the model is unknown until setup asks: make the offer without a name or size. oMLX picks the model for this computer (CORSIA's starter model when oMLX has none), never you; never name another.
2. Ask once, in chat, then end your turn and wait:

> A model that runs on this computer is for work you'd rather keep local and for background jobs. I'd set up [name] ([download_size_gb] GB). It downloads in the background, and the app shows progress. It uses memory while it's loaded. Installing it doesn't move any work by itself; afterwards I can point particular agents or jobs at it if you want. Set it up?

With no model picked, say `the model that suits this computer best` in place of `[name] ([download_size_gb] GB)`.

3. Yes: `POST /api/providers/local/setup` with body `{}`; setup installs the model it picked. The disk needs room for the rest of the download plus 10%. Report progress truthfully from `GET /api/providers/local/setup` (`state`, `percent`, `eta_seconds`, `stalled`); never promise a speed. Handle failures using `cause`, `ref` and `bytes_to_free` as below. A `409` with `detail.code` `consent_required` means an unregistered copy of oMLX is running on this computer: ask the person whether to stop theirs or keep both running, then resend the same request with `"other_omlx": "stop"` or `"keep"`. Registered servers and CORSIA's supervised processes are never offered to stop. A `409` `foreign_omlx_changed` means the running copies changed since you asked, or stopping them failed: ask again, then resend. If it is still `downloading`, follow **Setup already running**; do not start it again.
4. No: move on. Don't re-offer unless they ask.

## Setup already running

It runs on its own and never holds up a setup task. For `starting`, post `Your local model is starting in the background. Your agents can use it once it's ready.` For `downloading`, post `Your local model is downloading in the background: [percent]%. Your agents can use it once it's done.` Omit the percent when it is null; if `stalled` is true, say the download is paused and continues when the connection returns. Then carry on with the rest of task 2.

While setup is open, read the same route again at the end of each later setup task, and whenever the person asks about it. Say nothing while it still runs unless asked. The first time it reads `ready`, re-check `model_sources` and, if connected, post `Your local model finished setting up. Your agents can use it now.` For `stopped`, say setup is stopped; never claim it completed or failed. For `setup_failed`, `start_failed` or `failed`, say once what failed: setup, starting the downloaded model, or the download respectively. Use `cause` for the next step: `disk_full` means free `bytes_to_free` bytes then retry in Settings; `connection` means check the connection then retry; `memory` means choose a subscription or API provider; `own_omlx_upgrade_required` means run `brew upgrade jundot/omlx/omlx` (or `brew reinstall jundot/omlx/omlx` for a broken installation), or install the CORSIA app to use its bundled oMLX. Otherwise suggest Retry or Save a report in Settings. Include `ref` when present. Never invent a `stage`, `result` or failure message field. If it is still `downloading` at the wrap-up, add the clause `The local model is still downloading; the app shows its progress.`
