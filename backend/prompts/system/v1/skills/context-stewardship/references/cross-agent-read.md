# Cross-agent read (project conductor or CORSIA)

Schedule nothing new; run this inside the wake or turn your conductor role context names. This is a bounded sampling read, not a per-thread ledger: record routed patterns only in their plan tasks, which remain the durable handoff surface. Do not keep a separate list of lesson ids or routes in a thread folder.

1. **Read.** A conductor reads its own project only: `lesson_report(scope="project", project=<your project id>, state="watch", preview=true)`, never another project id or `scope="all"`. The CORSIA agent reads every project: `lesson_report(scope="all", state="watch", preview=true)`, with no `project`. Then make the same call once again with `state="trial", preview=true`. Do not follow `next_cursor`: each scheduled read is capped at two report calls and ten due-first rows. Before routing a pattern, check the plan for an existing task covering that same pattern; continue it instead of creating a duplicate. An empty read means no current lesson was returned; it does not establish that no cross-agent pattern exists. Read any other lesson source your coordination model names with its own bounded procedure.
2. **Restate each returned item** in one line: the decision that went wrong, with no names, dates, ids or task details. Write its cause beside it, using the seven causes in `memory-placement` §4 (wrong rule, no foundation, rule gap, process gap, not delivered, not followed, can't be done); use the item's own recorded cause when it has one. Before writing *rule gap*, search the guidance the owner was delivered (System context and skills, project context, its own bootloader and skills; read them through the effective-context view if you have one, else the source files by layer, and say which you used) for a rule that already covers the decision; if one does, the cause is *not delivered* when that rule never reached the owner's turn (wrong layer, or a skill that didn't trigger), *not followed* when it did, and *wrong rule* when following it produced the bad decision; never *rule gap*.
3. **Group.** Two items are the same pattern when the same decision went wrong for the same cause. Matching words, the same topic, or the same person's name do not make a pattern. A group needs at least two different owners (`owner_ids`). One owner repeating itself is its own lesson's business; leave it. Test each pair by asking whether one fix would help both; if a fix for one would make the other worse, they are different patterns. As the CORSIA agent, the owners must also span two or more projects (each row's `project_ids`; a row without them counts for none); skip a group inside one project, which is its conductor's.
4. **Route each group** by `SKILL.md`'s Prove it and Promote. Write the scenario set from the items (the failing task shape, an ordinary success, a boundary case that must not trigger). Then apply the remedy `memory-placement` §4 gives for that cause, at the shared layer: place a project-layer rule yourself; for a System one, follow Promote's upstream route; for *not followed*, write no new text and recommend a control, as an option, to whoever owns the gate or tool. Never edit another agent's guidance or lesson file. Tell each affected owner once, through the route your coordination model gives the conductor for cross-agent patterns (a plan task on the owner's plan where allowed, never a direct message per agent), carrying the group line and the lesson ids. When most of the project's agents share the pattern, use one project-wide notice instead. As the CORSIA agent, fix at the workspace layer or upstream, never in a project's files; tell the owners through one workspace-wide notice when most projects share the pattern, otherwise once to each affected project's conductor, never to its agents.
5. **If nothing matches, route nothing.** Send no message and add no plan node. Write to the person only as `SKILL.md`'s Learning reports says.
