# Connect Microsoft

Only the designated CORSIA thread runs this. Never ask for, type, read, print or paste a password, code, card number, client secret or token.

1. Load pack `microsoft` with `tools_load` and call `microsoft_status` with no `account_id`. It lists every Microsoft row with its address, kind and state, or says not_connected. If the account the person means is connected, post `Connected as <address>.` and stop. If it gives needs_action for that account, follow that instead of this skill.
2. Know the kind before the offer. An address ending in `outlook.com`, `hotmail.*`, `live.*` or `msn.com` is personal. Otherwise ask once: `Is this a personal Outlook.com account, a work or school account, or both?` Record it only for this connection. Both registers in the work tenant, so it gets no Azure line.
3. Post: `I can look after your Outlook mail, calendar and files. To connect them, I’ll set up your own private Microsoft app in a browser you can watch, and you sign in and click Accept. Microsoft may label the app unverified. That’s normal for an app you own; it only reaches the account you choose.` Personal only adds: `Microsoft needs a free Azure account to register the app. It asks for a card and phone to prove you’re a person; there’s no charge. Go ahead?` Wait for yes. Not now: `Ask me any time to connect your Outlook account.`
4. Open `https://entra.microsoft.com` with `browser_open` and `show_window: true`. If it fails asking to install agent-browser, do exactly what google-setup step 4 says. A sign-in, password, MFA, passkey, card, phone or verification-code page belongs to the person: follow `.corsia/skills/conductor-bootstrap/references/browser-person-steps.md` B. A terms page or a captcha: follow A. Take over once the URL or title shows they are past it.
5. Personal no-directory/Microsoft Services: open Azure’s free-account path; wait for the person to complete card, phone and terms. Return to Entra and confirm a tenant name. If they say not now, or B's watch ends and their reply (C of that file) says they're stopping, do step 16, then post `Setup paused. Ask me to connect Outlook whenever you’re ready.` A watch that ends with no reply is not a pause: post B's `Tell me when you're past it` line.
6. Work account with unavailable App registrations/Register: post the fixed registration-disabled text and IT message. Do step 16, then stop; do not work around the tenant.
7. Open App registrations > New registration. If `CORSIA` already exists, open it and read its Supported account types. If they fit step 2's kind, reuse it and skip to step 11. If not, stop with the named setup block for an incompatible account type (signInAudience can't change); never create a second one. Select personal only, work only in its tenant, or work-and-personal from step 2. Leave Redirect URI blank and register.
8. Authentication > Add Redirect URI > Mobile and desktop applications: add `http://localhost`. Do not add wildcard, secret or `127.0.0.1`.
9. Authentication > Settings: set Allow public client flows to Yes and save. Treat the setting as provisional: the real-account run determines whether the loopback redirect actually needs it.
10. API permissions > Add a permission > Microsoft Graph > Delegated: add exactly `Mail.ReadWrite`, `Mail.Send`, `Calendars.ReadWrite`, `Files.ReadWrite`, `offline_access`, `User.Read`. Do not press Grant admin consent. Take no Entra or Azure action outside steps 7 to 11: no subscriptions, role assignments, secrets or certificates, and never Upgrade or pay-as-you-go.
11. Read Application (client) ID and, for work, Directory (tenant) ID. No secret is created or downloaded.
12. Call `microsoft_connect` with `client_id`, `kind` (`personal`, `work` or `both`) and, for `work` only, `tenant_id`. It refuses anything that isn't a GUID or one of those kinds, and returns a sign-in link.
13. Post: `Open this link, sign in with the Microsoft account you just used, and click Accept. Microsoft may label the app unverified; it’s your own CORSIA app.` The link opens in the person's default browser, never the agent browser, and the agent does not watch that page: its final redirect carries an authorization code, which must never reach a model.
14. Success: call `microsoft_status` and post `Connected as <address>.` Approval required: use the fixed A10 state and IT message. Cancellation: use the quiet cancellation state.
15. If a browser step fails, ask the person to do only that step on the page already open. Never hand over the complete list.
16. Before ending, whether setup succeeded or paused: in the agent browser, open the Microsoft account menu, choose Sign out, and confirm it by URL and title. This isn't a person page, so you may click. Setup otherwise leaves a signed-in Microsoft session any agent could drive (for a personal account, Global Admin of the new tenant).
