# Connect Google

Only the designated CORSIA thread runs this. The person does two things: signs in to Google in the browser you open, and clicks Allow on the sign-in link. You do every other step. Never ask for, type, read, print or paste a password, code, client secret or token.

1. Load pack `google` with `tools_load` and call `google_status`. It lists every account with its `account_id`. If the person means an account listed there, ask which one first when more than one could be meant; if that account shows `needs_action`, follow that instead of this skill. Otherwise call `google_connect` with that `account_id`, post its `reply` verbatim with `post_update` followed by `[Open it in Connected apps](<link>)`, and stop. To connect a new account, including the first, go on to step 2.
2. Post with `post_update`: `I can look after your email and calendar. To connect them, I'll set up your own private Google project in a browser you can watch, and you sign in and click Allow. Google will also ask for your Drive, Docs and Sheets, so you won't have to sign in again later. Two things to expect: Google may warn that the app isn't verified. That's normal for a private project like yours; choose "Advanced", then "Go to CORSIA (unsafe)". It's your own project, so you're the only one it can reach. And the project may get published as "In production", because a project left in Testing stops letting me in after 7 days. Go ahead?` Wait for their yes. On "not now": `Ask me any time to connect your email.`
3. Call `google_connect` with no `client_file`. If it returns a link, a client is already saved: go to step 6. If it says no Google client is saved, go on.
4. Open `https://console.cloud.google.com/projectcreate` with `browser_open`. Do not set `show_window`: the shared browser is already available. If the error says to reinstall or update CORSIA, the app's own browser is broken, a gap in CORSIA: tell the person in plain words to reinstall or update CORSIA, report it the way you report any problem with CORSIA, and stop. If it names install commands instead (CORSIA run from source), call `request_host_access` for exactly those commands, stating that the person asked to connect Google and that nothing else is installed or changed. Once approved, run them with host scope, tell the person the browser download takes a few minutes, then call `browser_open` again. If access is refused, give the person those commands to run in Terminal and wait until they say it finished.
5. In the shared browser from step 4: a sign-in, password, 2-Step or passkey page belongs to the person: follow `.corsia/skills/conductor-bootstrap/references/browser-person-steps.md` B. A terms page or a captcha: follow A of that file. Once they are past it, take over. Open each link given rather than hunting through menus; if one lands on a different page, search the console for that page's name.
   a. Create a project named `CORSIA` once. After you submit it, Google can briefly alternate between its dashboard and a creation error while the project provisions. Do not revisit `projectcreate` or submit Create again: wait for the project selector to show `CORSIA` as the current project, then continue. If it does not appear after about 5 minutes, first check whether the selector lists `CORSIA`: select it if it does; otherwise ask the person to complete only the project-creation step in the page already open. Never make a second project or client.
   b. Open `https://console.cloud.google.com/flows/enableapi?apiid=gmail.googleapis.com,calendar-json.googleapis.com,drive.googleapis.com,docs.googleapis.com,sheets.googleapis.com`, check that the `CORSIA` project is selected, and confirm. That enables all five APIs.
   c. Open `https://console.cloud.google.com/auth/branding`: user type Internal when Google offers it (only a project inside a work organization gets it), otherwise External; app name `CORSIA`, and the signed-in address as both the support and the developer email.
   d. Skip this step if you chose Internal. Open `https://console.cloud.google.com/auth/audience`, press Publish app and confirm. Read the page again; go on only when it says In production. If you can't press it, ask the person to press Publish there and tell you when it says In production.
   e. Open `https://console.cloud.google.com/auth/clients`, press Create client, application type Desktop app, name `CORSIA`, Create. The dialog that opens shows the client secret, so take no snapshot or screenshot of it: press its Download JSON with one `browser_eval` of `[...document.querySelectorAll('button')].find(b => b.textContent.includes('Download JSON')).click()`, `browser_wait` 3000 milliseconds for the download, then drop the dialog with one `browser_eval` of `location.reload()`. Read the client ID from the Clients list. The file is `~/Downloads/client_secret_<client ID>.json`; never open it.
   If Google says their organization doesn't allow creating projects or this app, post that in plain words, add one sentence they can send their admin, and stop: create no client and try no other route. If any other step fails in the browser, ask the person to do only that step, at the page you have open. Never hand them the whole list.
6. Call `google_connect` with `client_file` set to that path as is (skip this call if step 3 already gave a link). It reads the file itself, so never list or check Downloads first and never request host access for it. If it says the file isn't a client file, ask the person where their browser saved `client_secret_<client ID>.json` and pass that path. Post the link in chat, never with `browser_open`: it opens in the person's own default browser. Post: `Open this link. It opens in your usual browser: pick the Google account you used for the project (sign in there if asked), and click Allow.` With External, add `When Google says the app isn't verified, choose Advanced, then Go to CORSIA (unsafe).`
7. When they say it's done, call `google_status` and post `Connected as <address>. If that's the wrong account, say so and I'll switch it.` If it still says not connected, post what it says.
