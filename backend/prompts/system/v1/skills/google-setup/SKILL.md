# Connect Google

Only the designated CORSIA thread runs this. The person does two things: signs in to Google once in the browser you open, and clicks Allow on each account's sign-in link. You do every other step, every Cloud console page included; never send the person to the console or hand them a list. Never ask for, type, read, print or paste a password, code, client secret or token.

1. Load pack `email` with `tools_load` and call `google_status`. It lists every account with its `account_id`. If the person means an account listed there, ask which one first when more than one could be meant; if that account shows `needs_action`, follow that instead of this skill. Otherwise call `google_connect` with that `account_id`, post its `reply` verbatim with `post_update` followed by `[Open it in Connected apps](<link>)`, and stop. To connect a new account, including the first, go on to step 2.
2. Post with `post_update`, as one sentence then two bulleted groups, in this order: `To connect Gmail and Calendar, CORSIA creates a private Google project you own, in a browser you can watch. Google will ask to:` then the bullets `Read, send and change your Gmail, and manage your calendar.` `See, edit and delete your Drive, Docs and Sheets files, so you won't have to sign in again later.` then `Two things to expect:` and the bullets `If Google warns the app isn't verified, choose "Advanced", then "Go to CORSIA (unsafe)". It's your own project, so only you can reach it.` `CORSIA may set the project to "In production", because a project left in Testing stops letting CORSIA in after 7 days.` then `Which Google accounts should I connect? List each address and I'll start.` Wait for the addresses. On "not now": `Ask me any time to connect your email.`
3. Call `google_connect` with no `client_file`. If it says no Google client is saved, go on to step 4. If it returns a link, a client is already saved, so go to step 6, except when an address from step 2 has a different domain from every address `google_status` lists (gmail.com counts as a domain of its own): then the project may be Internal, which refuses that address. Open `https://console.cloud.google.com/auth/audience` as step 4 says, with step 5's rule for pages that are the person's, in the `CORSIA` project; if it says Internal, press Make external and confirm, do step 5c, then go to step 6.
4. Open `https://console.cloud.google.com/projectcreate` with `browser_open`. Do not set `show_window`: the shared browser is already available. If the error says to reinstall or update CORSIA, the app's own browser is broken, a gap in CORSIA: tell the person in plain words to reinstall or update CORSIA, report it the way you report any problem with CORSIA, and stop. If it names install commands instead (CORSIA run from source), call `request_host_access` for exactly those commands, stating that the person asked to connect Google and that nothing else is installed or changed. Once approved, run them with host scope, tell the person the browser download takes a few minutes, then call `browser_open` again. If access is refused, give the person those commands to run in Terminal and wait until they say it finished.
5. In the shared browser from step 4: a sign-in, password, 2-Step or passkey page belongs to the person: follow `.corsia/skills/conductor-bootstrap/references/browser-person-steps.md` B. A terms page or a captcha: follow A of that file. Once they are past it, take over in that window. `browser_run_steps` runs a step file CORSIA ships and stops at the first step it can't finish, naming it with its `says`. If the result says the person declined, follow its message and stop. If an `ok` result carries a message, hand the page to the person as `browser-person-steps.md` says, then continue the skill without calling the file again. Otherwise, if it carries `start_at`, the page is the person's: hand it over as `browser-person-steps.md` says, then call again with the same `steps` and that `start_at`. On any other stop, do that step and the rest of that file (`.corsia/skills/google-setup/steps/<name>.json`; each step's `says` is what to do) yourself, and report the stop's `step` and `saw` the way you report any problem with CORSIA.
   a. If the console already has a project named `CORSIA`, select it; otherwise run `steps: "google-setup/console-project"` to create it. After you submit it, Google can briefly alternate between its dashboard and a creation error while the project provisions. Do not revisit `projectcreate` or submit Create again: wait for the project selector to show `CORSIA` as the current project, then continue. If it does not appear after about 5 minutes, first check whether the selector lists `CORSIA`: select it if it does; otherwise treat it as a failed step (end of step 5). Never make a second project. Once the selector shows `CORSIA` as the current project, run `steps: "google-setup/console-apis"` to enable the five APIs.
   b. Choose the audience from the step 2 addresses: Internal only when Google offers it (only a project inside a work organization gets it) and every address is in the signed-in account's domain; otherwise External. Open `https://console.cloud.google.com/auth/branding`, pick that user type, app name `CORSIA`, the signed-in address as both the support and the developer email, then Save. If it already shows app name `CORSIA`, an earlier run saved it: leave it, open `https://console.cloud.google.com/auth/audience`, and when it says Internal and you need External, press Make external and confirm.
   c. Skip this if you chose Internal. Open `https://console.cloud.google.com/auth/audience`, press Publish app and confirm. Read the page again; go on only when it says In production.
   d. Run `steps: "google-setup/console-client"`. It creates a Desktop client `CORSIA`, downloads its JSON and reloads to close the dialog that shows the client secret. Run it even when the Clients list already has a `CORSIA` client: Google shows a secret only when it makes it, so an old client's JSON can't be downloaded again. Leave the old client alone; another CORSIA may use it, and Google deletes clients unused for six months. If it stops at `download-json` or a later step, the dialog that shows the client secret may still be open, so take no snapshot or screenshot of it: call again once with `start_at` set to the step it stopped at. Read the new client's ID from the Clients list: with two `CORSIA` rows, it is the one with the latest creation date. The file is `~/Downloads/client_secret_<client ID>.json`; never open it.
   If Google says their organization doesn't allow creating projects or this app, post that in plain words, add one sentence they can send their admin, and stop: create no client and try no other route. If a console step still fails after one retry, report it the way you report any problem with CORSIA, then ask the person for only that click, at the page you have open.
6. Get one link per step 2 address `google_status` doesn't list as connected (step 3's link counts as the first): call `google_connect` with `client_file` set to that path as is, the same file for every link (no `client_file` when step 3 returned a link). It reads the file itself, so never list or check Downloads first and never request host access for it. If it says the file isn't a client file, ask the person where their browser saved `client_secret_<client ID>.json` and pass that path. Post all the links in one `post_update`, never with `browser_open`: they open in the person's own default browser. Post: `Open each link in your usual browser, pick the account named next to it (sign in there if asked), and click Allow.` then one line per link, `<address>: <link>`. With External, add `When Google says the app isn't verified, choose Advanced, then Go to CORSIA (unsafe). When it lists what CORSIA can access, tick every box before you continue.`
7. CORSIA wakes you as each link finishes or expires. Call `google_status`: each account's `scopes` should hold the `gmail`, `calendar`, `drive`, `documents` and `spreadsheets` scope URLs. Post `Connected as <address>.` for each, adding `Google didn't give CORSIA Drive, Docs and Sheets, so only email and calendar work. To add them, remove <address> in Connected apps, then ask me to connect it again and tick every box.` for one missing those, and `If that's the wrong account, say so and I'll switch it.` once. For an expired or not-connected address, post what `google_status` says and offer a new link from `google_connect`.
